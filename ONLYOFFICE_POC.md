# ICAT × ONLYOFFICE: изолированный прототип

> **АРХИВНЫЙ ЭКСПЕРИМЕНТ.** ONLYOFFICE не является основой текущей реализации. Актуальное ТЗ: [TECHNICAL_SPECIFICATION.md](TECHNICAL_SPECIFICATION.md).

Прототип проверяет одну гипотезу: сможет ли полноценный офисный движок показывать и сохранять сложные DOCX точнее, чем собственная браузерная пагинация ICAT Grid.

Эксперимент находится в ветке `experiment/onlyoffice-integration`. Исходное состояние сохранено в `main` и отмечено тегом `before-onlyoffice-poc-20260902`.

## Что добавлено

- отдельный Docker Compose-сервис ONLYOFFICE Document Server;
- отдельная страница `/onlyoffice.html`, не заменяющая существующий редактор;
- локальная загрузка и хранение DOCX в `data/onlyoffice`;
- подписанная JWT-конфигурация редактора;
- callback сохранения изменённого файла из ONLYOFFICE обратно в ICAT;
- скачивание последней сохранённой версии DOCX;
- повторное открытие локального документа по URL с параметром `?document=ID`;
- проверка доступности Document Server.
- боковая CAT-панель с сегментами исходного текста и полями чернового перевода;
- серверная OOXML-сегментация абзацев, таблиц, текстовых полей, колонтитулов и сносок;
- структурные адреса и детерминированные ID сегментов вместо экранных координат;
- поиск по сегментам, прогресс перевода и локальное сохранение черновиков в браузере.

`data/onlyoffice` и локальный `.env.onlyoffice` исключены из Git. Эксперимент не использует Google Docs и не загружает документы в облако ONLYOFFICE.

## Запуск

1. Запустить Document Server:

   ```bash
   npm run onlyoffice:up
   ```

   При первом запуске Docker загружает большой образ. Последующие запуски значительно быстрее.

2. Запустить ICAT с адресом, доступным Docker-контейнеру:

   ```bash
   HOST=0.0.0.0 npm start
   ```

3. Открыть:

   - эксперимент: <http://127.0.0.1:3100/onlyoffice.html>;
   - исходный редактор: <http://127.0.0.1:3100/>.

4. Загрузить DOCX. Для принудительной передачи текущей версии в ICAT нажать значок сохранения внутри ONLYOFFICE, затем дождаться сообщения `DOCX сохранён в ICAT`.

5. Скачать сохранённый файл верхней кнопкой и открыть его в Microsoft Word.

## Остановка

```bash
npm run onlyoffice:down
```

Команда останавливает контейнер, но сохраняет именованные Docker volumes. Файлы, загруженные через ICAT, находятся в игнорируемой папке `data/onlyoffice`.

## Настройки

Значения по умолчанию подходят для Docker Desktop на macOS:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `ONLYOFFICE_PORT` | `8080` | Порт Document Server на компьютере |
| `ONLYOFFICE_SERVER_URL` | `http://127.0.0.1:8080` | Адрес API для браузера и ICAT |
| `ONLYOFFICE_DOWNLOAD_URL` | `http://127.0.0.1:8080` | Адрес загрузки результата callback |
| `ONLYOFFICE_INTERNAL_APP_URL` | `http://host.docker.internal:3100` | Адрес ICAT, видимый из контейнера |
| `ONLYOFFICE_JWT_SECRET` | тестовый локальный ключ | Общий JWT-ключ ICAT и Document Server |

Шаблон находится в `.env.onlyoffice.example`. Для production необходимо заменить JWT-ключ, включить HTTPS, закрыть прямой публичный доступ к исходным файлам и добавить авторизацию callback.

Если значения меняются, их нужно экспортировать в текущую shell-сессию перед запуском Docker и Node. Оба процесса обязаны получить одинаковый `ONLYOFFICE_JWT_SECRET`.

## Как проходит документ

```text
Браузер → POST DOCX → ICAT storage
                         ↓
               временный URL + JWT config
                         ↓
Браузер ← UI редактора ← ONLYOFFICE Document Server
                         ↓ сохранение/callback
Браузер ← download ← ICAT storage с новой версией DOCX
```

Document Server не является базой документов. Он получает файл от ICAT для сессии редактирования, а после сохранения сообщает ICAT адрес готовой версии. ICAT скачивает её и заменяет локальный файл атомарно.

## Границы первого этапа

- черновики перевода пока не подставляются обратно в DOCX и хранятся только в текущем браузере;
- выбор сегмента пока не переводит курсор ONLYOFFICE к соответствующему месту;
- пока нет памяти переводов и базы знаний;
- нет совместной работы и пользовательской авторизации;
- локальное хранилище предназначено только для POC;
- callback защищён архитектурой локальной сети, но пока не проверяет входящий JWT;
- точность зависит от наличия на Document Server тех же шрифтов, которые использует исходный DOCX;
- ONLYOFFICE может отображать документ немного иначе, чем Microsoft Word, но не должен разрушать таблицы и поток текста так, как это делает текущая абсолютная раскладка сегментов.

Следующее решение принимается только после сравнения нескольких реальных исходников и сохранённых DOCX в Word.

## Первый проверенный документ

Проверен `/Users/yuriybevov/Downloads/1_TZ_schema_org_bitrix_RISE.docx`, на котором собственная браузерная сегментация накладывала таблицы с кодом друг на друга.

- Microsoft Word определил 9 страниц.
- ONLYOFFICE сформировал 9 страниц без визуальных наложений.
- Редактор полностью загрузился в headless Chrome и сообщил `Документ готов к редактированию`.
- Callback вернул редактируемый DOCX в ICAT и увеличил локальную ревизию.
- Полученный файл открылся Microsoft Word без восстановления и сохранил 9 страниц.
- Исходный и сохранённый DOCX содержат одинаковые 261 абзац, 19 таблиц и 17 113 текстовых символов.
- SHA-256 объединённого содержимого всех `w:t` совпал, то есть при тестовом round-trip текст не изменился.

Предыдущий контроль через Apple Pages показывал 12 страниц. Это оказалось различием движков: канонический для данного теста Microsoft Word, как и ONLYOFFICE, рассчитывает 9 страниц.
