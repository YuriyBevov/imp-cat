# Отчёт тестирования ICAT Grid

Дата проверки: 1 сентября 2026 года.

## Исправление по результатам ручной проверки

Первоначально документ отображался, но счётчик показывал 0 сегментов. Причина: HTML-страницы DOCX измерялись, пока родительский контейнер имел атрибут `hidden`, поэтому `getBoundingClientRect()` возвращал нулевые размеры. Исправлено: перед извлечением текста страница временно участвует в layout с `visibility: hidden`, после чего строятся сегменты и интерфейс становится видимым.

При следующей проверке длинный экспорт смешивал координаты. Причины: длинная DOM-страница ограничивалась сервером до 5000 px, а legacy-абзацы `framePr` оставались участниками потока Word. Исправлено: добавлена виртуальная пагинация и абсолютное позиционирование блоков относительно страницы.

Проблемный экспорт с 90 WPS/DrawingML-фигурами не открывался в Microsoft Word. Для максимальной совместимости экспорт переведён на прямые редактируемые `w:pict/v:shape` без WPS, `mc:AlternateContent` и `framePr`. VML-координаты записываются относительно страницы.

Последний пользовательский экспорт с 73 VML-блоками был корректным ZIP и содержал синтаксически правильный XML, но нарушал служебные инварианты Word: `_x0000_t202` объявлялся 73 раза, фактические `o:spid` доходили до `_x0000_s1097`, а `spidmax` оставался равным `1027`. В исправленном экспортере `shapetype` объявляется один раз, ID уникальны, а `spidmax` рассчитывается выше последнего ID. После сохранения экспортер повторно открывает пакет и отклоняет результат при повреждённом ZIP/XML, несовпадении страниц/сегментов или нарушении VML-инвариантов.

Причина значительной части наложений при импорте установлена на исходном файле: родительский абзац плавающей фигуры содержал объединённый текст длиной 1604 символа и импортировался вместе с вложенными абзацами. Теперь одна плавающая Word-фигура становится одним сегментом, а родительский контейнер не дублируется.

Для насыщенных документов добавлены сетка на всю рабочую область, бордер текстовой области Word, плавный экранный масштаб 25–250%, `Cmd/Ctrl + колесо` под курсором, режим «По ширине поля», рамочное выделение, групповое перемещение, счётчик пересечений и управляемое вертикальное разнесение. Реальное расширение высоты поля 100–400% сохранено; границы будущих Word-страниц отмечаются отдельно.

## Автоматические проверки

Команда:

```bash
npm run check
```

Результат: успешно.

- синтаксис `server.cjs` — успешно;
- синтаксис `public/app.js` — успешно;
- Node.js unit-тесты — 11/11;
- Python-тесты генерации DOCX — 2/2;
- повторяющиеся ID и некорректные страницы отклоняются;
- координаты ограничиваются геометрией страницы;
- ID ячейки вычисляется из координат;
- длинная DOM-страница корректно делится на виртуальные страницы;
- двухстраничный DOCX содержит независимые VML-блоки с ожидаемыми координатами;
- стресс-тест создаёт 240 блоков без единого `framePr`;
- экранная дельта drag/resize корректно пересчитывается при масштабе 25–250%;
- значимые пересечения находятся и вертикально разрешаются без сдвига соседних колонок;
- рамка корректно определяет пересекающиеся сегменты, а групповая дельта ограничивается физической страницей;
- рабочее поле расширяется и не обрезает сегменты за пределами исходной страницы;
- HTML-контролы масштаба связаны с обработчиками приложения;
- новый экспорт не содержит WPS/DrawingML и `mc:AlternateContent`;
- стресс-тест 240 сегментов подтверждает один `shapetype`, 240 уникальных `o:spid` и достаточный `spidmax`.

## Интеграционный HTTP smoke-тест

Работающий сервер на `127.0.0.1:3100` проверен после изменений.

| Проверка | Результат |
| --- | --- |
| `GET /api/health` | `200`, 15 байт |
| `GET /api/sample` | `200`, 37 302 байта |
| `POST /api/export` | `200`, новый DOCX; повторная ZIP/XML/VML-проверка успешна |

Экспортированный файл повторно открыт библиотекой `python-docx`:

- текст `Первая страница`, `Вторая страница` сохранён в редактируемых VML-блоках;
- секций: 2;
- позиционированных DrawingML-якорей: 0;
- VML-блоков: 2;
- legacy-рамок `framePr`: 0;
- первый блок расположен в `margin-left=48 pt`, `margin-top=60 pt`, что соответствует `64 × 80 px`.

## Невыполненные визуальные проверки

- Интерактивный браузер недоступен в текущей среде (доступных browser bindings: 0), поэтому автоматический click-through загрузки, рамочного выделения и группового drag не выполнен.
- Канонический DOCX-рендерер недоступен: в проектном окружении отсутствует `pdf2image`, а системный LibreOffice/`soffice` не установлен.
- Вместо LibreOffice выполнен Quick Look-рендер нового DOCX: первая страница и позиционированный текст отображаются.
- Исправленная копия реального 73-сегментного экспорта прошла повторное открытие через `python-docx`, проверку четырёх секций, 73 VML-блоков, ZIP и всех XML-частей. Окончательное подтверждение открытия нового скачанного файла в настольном Word остаётся ручным шагом.

Для окончательной приёмки интерфейса нужно вручную открыть `http://127.0.0.1:3100`, нажать «Открыть пример» и пройти сценарий из раздела ниже.

## Ручной сценарий приёмки

1. Открыть встроенный пример и убедиться, что появились страницы и рамки сегментов.
2. Выбрать сегмент и проверить ID ячейки в инспекторе.
3. Изменить текст сегмента.
4. Перетащить сегмент; проверить привязку к сетке и изменение ID ячейки.
5. Изменить размер за нижний правый маркер.
6. Открыть меню сегмента и проверить сброс, удаление и перенос между страницами.
7. Скрыть и снова показать сетку.
8. Удерживая `Cmd` (macOS) или `Ctrl` (Windows/Linux), прокрутить колесо над документом; убедиться, что точка под курсором сохраняется, а координаты в инспекторе не меняются.
9. Нажать «По ширине поля» и проверить автоматическое заполнение рабочей области.
10. Проверить зелёный бордер текстовой области Word; выбрать блок в поле и убедиться, что инспектор показывает «Поле страницы».
11. При наличии пересечений нажать «Разнести наложения» и проверить уменьшение счётчика.
12. Протянуть рамку левой кнопкой мыши по нескольким сегментам, затем перетащить `⠿` одного из них и проверить групповой сдвиг.
13. Установить высоту рабочего поля 200%, проверить красную пунктирную границу дополнительной Word-страницы и увеличение числа экспортных страниц.
14. Нажать «Выгрузить DOCX», открыть новый файл в Word и проверить отсутствие прежней ошибки открытия и доступность редактирования текста.
