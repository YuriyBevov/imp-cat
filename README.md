# ICAT Translation Studio

ICAT — прототип рабочего места бюро переводов для PDF, сканов и изображений. Актуальные требования, архитектура и критерии приёмки находятся в [TECHNICAL_SPECIFICATION.md](TECHNICAL_SPECIFICATION.md). Устаревшие эксперименты перечислены в [ARCHIVE_INDEX.md](ARCHIVE_INDEX.md).

Рабочая ветка `experiment/codex-document-agent` использует один мультимодальный агент как основной источник текста, структуры и координат. Предыдущая стабильная RapidOCR-версия сохранена в ветке `experiment/client-requirements-v2`.

## Текущий сценарий

1. Сервер принимает один или несколько PDF/изображений, сразу создаёт фоновые задания и сохраняет оригиналы локально.
2. PyMuPDF/Pillow только рендерят страницы в PNG; локальное извлечение текста не выполняется.
3. Выбранный единый AI-маршрут — Codex CLI или AITunnel API — передаёт изображения страниц мультимодальной модели и получает структурированный JSON.
   Многостраничные файлы автоматически обрабатываются последовательными пакетами по две страницы, но остаются одним заданием в интерфейсе.
   Приложение не уменьшает `max_output`: каждый пакет получает полный лимит, опубликованный для выбранной модели. Если каталог его не сообщает, `max_tokens` не передаётся.
   Загрузка записывает большой файл на диск потоково, не удерживая его целиком в памяти Node.js. Лимит по умолчанию — 300 МБ; он настраивается через `DOCUMENT_UPLOAD_MAX_MB`.
4. Агент извлекает полный текст, логические сегменты, порядок чтения, координаты, типографику и специальные объекты: таблицы, печати, штампы, подписи, рукописный текст, логотипы и изображения.
5. Сервер проверяет ответ и преобразует нормализованные координаты в `DocumentScene`.
6. Редактор показывает задания и документы во вкладках, оригинал рядом с рабочей страницей и даёт править текст, перевод, стили, размеры, расположение и состав сегментов.
7. В режиме «Сегменты» исходник и перевод расположены в двух синхронных колонках. Чекбоксы позволяют отправить на перевод произвольный пакет или сразу все переводимые сегменты документа.
8. Утверждённая сцена экспортируется детерминированным кодом в DOCX или PDF.

Завершённые проекты восстанавливаются из локального серверного хранилища после перезагрузки страницы и снова отображаются во вкладках. Неуспешное задание переходит в конечное состояние ошибки и больше не опрашивается браузером. Кнопка «Повторить обработку» создаёт новое задание для уже сохранённого исходника с текущим AI-маршрутом — повторно загружать файл не нужно.

Файлы и проекты хранятся локально. Изображения страниц покидают сервер только при обращении к выбранному AI-маршруту: OpenAI через авторизованный Codex CLI либо AITunnel по HTTPS. Единственным источником текста и структуры является выбранная мультимодальная модель.

## Локальный запуск

Требования:

- Node.js 22+;
- Python 3.11+;
- установленный Codex CLI;
- выполненный вход `codex login` через ChatGPT.

```bash
cd /Users/yuriybevov/Desktop/local-projects/icat-test
npm install
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
npm start
```

Откройте [http://127.0.0.1:3100](http://127.0.0.1:3100).

Проверить авторизацию агента:

```bash
codex login status
```

Основные настройки `.env`:

```dotenv
AI_PROVIDER=codex
CODEX_BIN=codex
CODEX_DOCUMENT_MODEL=gpt-5.6-sol
CODEX_DOCUMENT_TIMEOUT_MS=900000
```

## AITunnel и Codex

Кнопка «AI-провайдер» выбирает единый маршрут для первичного распознавания и сегментации, повторного анализа и перевода:

- AITunnel API — ключ вводится в интерфейсе, передаётся backend в RSA-OAEP-шифротексте и может быть сохранён в серверном `.env`;
- Codex — используется существующий вход `codex login` через ChatGPT, API-ключ не нужен.

Список моделей AITunnel загружается из актуального публичного каталога. Для выбора доступны модели с входной модальностью `image` и текстовым ответом. Кнопка «Проверить подключение» проверяет ключ и доступность выбранного ID через авторизованный каталог AITunnel, не запуская платную генерацию.

При отмеченном «Сохранить ключ на сервере» backend атомарно записывает его в `.env` с правами `0600`. `.env` исключён из Git, не раздаётся веб-сервером, а значение ключа не возвращается API. Файл хранит секрет в открытом виде и должен быть доступен только серверному пользователю. Сервер принимает только HTTPS endpoint провайдера; в production сам ICAT также должен работать через HTTPS.

Ключ также можно задать в `.env` сервера вручную:

```dotenv
AI_PROVIDER=aitunnel
TRANSLATION_API_KEY=
TRANSLATION_MODEL=
```

Предыдущий кроссплатформенный RapidOCR/ONNX сохранён только в архивной ветке `experiment/client-requirements-v2`. В текущей ветке его код и зависимости удалены; ошибка выбранного AI-маршрута показывается пользователю без скрытого fallback.

## Проверки

```bash
npm run check
```

Команда проверяет JavaScript, JSON Schema, Python-модули, модель сцены, историю, геометрию, агентный адаптер и генерацию документов.

## Основные файлы

- `lib/document-agent.cjs` — запуск Codex, промпт и нормализация ответа;
- `lib/api-document-agent.cjs` — тот же контракт анализа через мультимодальную модель AITunnel;
- `lib/document-batching.cjs` — пакетная обработка больших документов и сборка единого результата;
- `lib/aitunnel.cjs` — живой каталог моделей и проверка подключения;
- `lib/credential-vault.cjs` — память процесса и RSA-OAEP-приём ключа AITunnel;
- `lib/env-credentials.cjs` — атомарное серверное хранение ключа в `.env` с правами `0600`;
- `lib/job-manager.cjs` — очередь фонового анализа документов;
- `schemas/document-analysis.schema.json` — контракт первичного анализа;
- `scripts/document_analyzer.py` — локальная подготовка PNG-страниц без извлечения текста;
- `lib/studio-model.cjs` — преобразование анализа в редактируемую сцену и QA;
- `lib/studio.cjs` — серверный API рабочего процесса;
- `public/studio.js` — визуальный редактор;
- `scripts/export_studio.py` — сборка DOCX/PDF.

## Ограничения текущего этапа

- Авторизация пользователей, совместная работа и политика хранения ещё не реализованы.
- Перевод через AITunnel/Codex реализован; качество переводческих промптов и терминологический контекст требуют отдельного этапа.
- Фоновые задания хранят статус в памяти процесса и при перезапуске сервера не возобновляются автоматически.
- Сырой текст ответа AITunnel без ключей и HTTP-заголовков сохраняется рядом с проектом. Для большого документа файлы имеют имена `aitunnel-analysis-response-batch-NNN.json`; нормализованные контрольные точки — `agent-analysis-batch-NNN.json`.
- Кнопка «Документы» показывает рабочие и архивные проекты. Архив сохраняет файлы; окончательное удаление требует подтверждения.
- Агентная визуальная корректировка готового макета пока описана в ТЗ, но ещё не применяет команды автоматически.
- Качество координат и типографики модели необходимо измерить на контрольных документах Arbel и UNH; редактор остаётся обязательным этапом контроля.
