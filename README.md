# ICAT Translation Studio

ICAT — прототип рабочего места бюро переводов для PDF, сканов и изображений. Актуальные требования, архитектура и критерии приёмки находятся в [TECHNICAL_SPECIFICATION.md](TECHNICAL_SPECIFICATION.md). Устаревшие эксперименты перечислены в [ARCHIVE_INDEX.md](ARCHIVE_INDEX.md).

Рабочая ветка `experiment/codex-document-agent` использует один мультимодальный агент как основной источник текста, структуры и координат. Предыдущая стабильная RapidOCR-версия сохранена в ветке `experiment/client-requirements-v2`.

## Текущий сценарий

1. Сервер принимает один или несколько PDF/изображений, сразу создаёт фоновые задания и сохраняет оригиналы локально.
2. PyMuPDF/Pillow рендерят страницы в PNG без предварительного OCR.
3. Установленный Codex CLI передаёт страницы модели `gpt-5.6-sol` и получает строгий JSON.
4. Агент извлекает полный текст, логические сегменты, порядок чтения, координаты, типографику и специальные объекты: таблицы, печати, штампы, подписи, рукописный текст, логотипы и изображения.
5. Сервер проверяет ответ и преобразует нормализованные координаты в `DocumentScene`.
6. Редактор показывает задания и документы во вкладках, оригинал рядом с рабочей страницей и даёт править текст, перевод, стили, размеры, расположение и состав сегментов.
7. В режиме «Сегменты» исходник и перевод расположены в двух синхронных колонках.
8. Утверждённая сцена экспортируется детерминированным кодом в DOCX или PDF.

Codex — облачная модель OpenAI. Файлы и проекты хранятся локально, однако изображения страниц во время анализа передаются OpenAI через авторизованный CLI. Сторонний OCR-сервис в основном маршруте не используется.

## Локальный запуск

Требования:

- Node.js 22+;
- Python 3.11+;
- установленный Codex CLI;
- выполненный вход `codex login` через ChatGPT.

```bash
cd /Users/yuriybevov/Desktop/local-projects/icat-test
npm install
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
npm start
```

Откройте [http://127.0.0.1:3100](http://127.0.0.1:3100).

Проверить авторизацию агента:

```bash
codex login status
```

Основные настройки `.env`:

```dotenv
DOCUMENT_ANALYSIS_MODE=codex
CODEX_BIN=codex
CODEX_DOCUMENT_MODEL=gpt-5.6-sol
CODEX_DOCUMENT_TIMEOUT_MS=900000
```

## AITunnel и Codex

Кнопка «AI-провайдер» позволяет выбрать способ автоматического перевода:

- AITunnel API — ключ вводится в интерфейсе, шифруется в браузере RSA-OAEP и хранится только в памяти Node.js-процесса;
- Codex — используется существующий вход `codex login` через ChatGPT, API-ключ не нужен.

При перезапуске приложения интерфейсный ключ AITunnel удаляется автоматически. Он не записывается в `.env`, `localStorage`, документы, логи или Git. Сервер принимает только HTTPS endpoint провайдера. Для сетевого production-развёртывания сам ICAT также должен работать через HTTPS: браузерное RSA-шифрование не заменяет TLS и проверку подлинности сервера.

Ключ по-прежнему можно задать локально через `.env`, который исключён из Git:

```dotenv
TRANSLATION_PROVIDER=aitunnel
TRANSLATION_API_KEY=
TRANSLATION_MODEL=
```

## Резервный OCR-режим

Предыдущий кроссплатформенный маршрут RapidOCR/ONNX сохранён только для диагностики и явного отката:

```dotenv
DOCUMENT_ANALYSIS_MODE=local
```

Приложение не переключается на него молча при ошибке Codex, потому что частичный OCR может создать ложное ощущение полноты документа.

## Проверки

```bash
npm run check
```

Команда проверяет JavaScript, JSON Schema, Python-модули, модель сцены, историю, геометрию, агентный адаптер и генерацию документов.

## Основные файлы

- `lib/document-agent.cjs` — запуск Codex, промпт и нормализация ответа;
- `lib/credential-vault.cjs` — временное защищённое хранилище ключа AITunnel;
- `lib/job-manager.cjs` — очередь фонового анализа документов;
- `schemas/document-analysis.schema.json` — контракт первичного анализа;
- `scripts/document_analyzer.py` — локальный рендер страниц и legacy OCR;
- `lib/studio-model.cjs` — преобразование анализа в редактируемую сцену и QA;
- `lib/studio.cjs` — серверный API рабочего процесса;
- `public/studio.js` — визуальный редактор;
- `scripts/export_studio.py` — сборка DOCX/PDF.

## Ограничения текущего этапа

- Авторизация пользователей, совместная работа и политика хранения ещё не реализованы.
- Перевод через AITunnel/Codex реализован; качество переводческих промптов и терминологический контекст требуют отдельного этапа.
- Фоновые задания хранят статус в памяти процесса и при перезапуске сервера не возобновляются автоматически.
- Агентная визуальная корректировка готового макета пока описана в ТЗ, но ещё не применяет команды автоматически.
- Качество координат и типографики модели необходимо измерить на контрольных документах Arbel и UNH; редактор остаётся обязательным этапом контроля.
