# Проверка ICAT Document Agent

Статус: актуальная инструкция для ветки `experiment/codex-document-agent`  
Дата: 5 сентября 2026 года

## 1. Подготовка

Проверьте зависимости и авторизацию:

```bash
cd /Users/yuriybevov/Desktop/local-projects/icat-test
codex login status
npm run check
```

Ожидается сообщение `Logged in using ChatGPT`, все JavaScript- и Python-тесты проходят без ошибок.

Основной режим задаётся в `.env` или используется по умолчанию:

```dotenv
AI_PROVIDER=codex
CODEX_DOCUMENT_MODEL=gpt-5.6-sol
CODEX_DOCUMENT_TIMEOUT_MS=900000
```

## 2. Запуск

```bash
npm start
```

Откройте [http://127.0.0.1:3100](http://127.0.0.1:3100). Под полем загрузки должно быть указано, что агент готов. Если кнопка выбора файла недоступна, сначала выполните `codex login`.

## 3. Первичный анализ

1. Выберите сразу два PDF/изображения.
2. Убедитесь, что для каждого файла появилась вкладка с независимым прогрессом. Между вкладками можно переключаться, пока задания продолжаются на backend.
3. Если задание завершилось ошибкой, нажмите **«Повторить обработку»**. Должно появиться новое фоновое задание для сохранённого исходника; повторный выбор файла не требуется. Сервер не допускает двойной повтор одного и того же ошибочного задания.
3. После открытия редактора проверьте число страниц и сегментов.
4. Переключитесь между режимами «Макет» и «Сегменты».
5. В левой панели последовательно откройте каждую оригинальную страницу.

Проверяемый результат:

- отсутствуют пустые или потерянные страницы;
- обычный текст, таблицы, ячейки, штампы, печати, подписи и рукописные области имеют правильный тип;
- у читаемых штампов и печатей сохранён текст;
- нечитаемые подписи обозначены типом и не содержат выдуманной транскрипции;
- сегменты находятся внутри соответствующей страницы;
- исходное соотношение сторон страницы не искажено.

## 4. Работа с сегментами

В режиме «Сегменты» проверьте двухколоночную строку для каждого объекта: исходный текст слева и независимое поле перевода справа. Затем проверьте добавление пустого сегмента, разделение по курсору, объединение выбранных, исключение из сборки, изменение шрифта и выравнивания, drag/resize, групповое выделение и `Cmd/Ctrl + Z`.

Кнопка «Повторить анализ исходника» заново запускает выбранный AI-маршрут по сохранённым изображениям страниц и заменяет текущую сегментацию. Перед запуском интерфейс предупреждает о потере ручных изменений; прежний `analysis.json` сохраняется в каталоге ревизий.

## 5. AI-провайдер

1. Нажмите «AI-провайдер».
2. Выберите AITunnel, выберите Vision-модель из загруженного каталога и укажите ключ.
3. Нажмите «Проверить подключение» и дождитесь подтверждения доступности выбранной модели.
4. Загрузите тестовое изображение и убедитесь, что `metadata.analysisMode` равен `aitunnel`; затем выполните повторный анализ и перевод.
5. Повторно откройте окно: интерфейс показывает только наличие ключа, но не его значение.
6. Переключитесь на Codex, проверьте подключение и повторите маршрут без API-ключа.
7. Оставьте включённой опцию сохранения, перезапустите backend и убедитесь, что AITunnel остался настроен, а значение ключа не показано в UI или API.

В production откройте Network Inspector и подтвердите HTTPS для ICAT и AITunnel. На локальном loopback ключ дополнительно защищён RSA-OAEP, но это не является заменой TLS для удалённого сервера.

## 6. Экспорт

1. Нажмите «Скачать DOCX».
2. Откройте документ в Word или LibreOffice и проверьте все страницы.
3. Нажмите «Скачать PDF» и проверьте число страниц, читаемость, наложения и выходы за границы.
4. Сегменты, помеченные как исключённые, не должны попадать ни в один формат.

## 8. Известные ограничения

- Очередь и статусы незавершённых заданий пока находятся в памяти backend: перезапуск процесса прерывает задания.
- Координаты специальных объектов соответствуют исходнику, поэтому печать или подпись может осознанно перекрывать основной текст.
- Агентная проверка уже отредактированного макета и применение её рекомендаций ещё не реализованы.
- Векторная база знаний и терминологический контекст относятся к следующему этапу.
